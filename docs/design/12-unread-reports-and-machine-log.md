# 12. 未読の報告・コンテキスト区画・機械用ログ（フェーズ② 2-6a）

- ステータス: **実装済み・検証済み（2026-10-18）**。結果は §8
- 位置づけ: `09-ai-office-redesign.md` §10 の 2-6（磨き込み）の最初の段階。
- 前提: 報告履歴（`08-report-history.md`）、状況サマリー・通知（09 §14）、プロジェクト切り替え（`11-project-switcher.md`）。

## 1. 目的

画面全体を見たときに、**対応が必要な情報だけが目立ち、詳しい情報は開いたときに見える**ようにする。

| 段階 | 内容 | 見せ方 |
|---|---|---|
| A: 対応が必要 | 許可待ち・エラー・**未読の報告** | 常に目立たせる（バッジ・ポップアップ・頭上の ✉） |
| B: 一目で分かればよい | 作業中／待機中・部屋 | 一覧の状態の点、キャラの動き |
| C: 必要なときだけ | 報告の本文・ツール・設定 | 開いたときだけ |

親子関係は **プロジェクト → 部屋 → エージェント → コンテキスト（1回の作業） → 報告**。
この段階（2-6a）では「エージェント → コンテキスト → 報告」の部分を作る。部屋ごとのまとめ・古い状態の表示は 2-6b 以降。

あわせて、人が読む画面とは別に、**PC 上で調査するための機械用ログ**を各エージェントごとに残す。保存場所は設定で変えられる。

## 2. ユーザーの決定（2026-10-18）

| 項目 | 決定 |
|---|---|
| 未読の通知 | エージェント一覧の右上に「未読 N件（M人）」。押すと誰が何件かの一覧。各行にも件数バッジ |
| 既読になるとき | そのエージェントの詳細パネルを開いたとき。レポート画面でそのエージェントに絞り込んだときも既読 |
| 未読として数える報告 | **結果（result）・警告（warn）・エラー（error）だけ**。「開始しました」などの info は数えない |
| 初めて開いたとき | 過去の報告も未読として数える（info を数えないので件数は多くならない）。その代わり、報告を**コンテキストごとに薄い境界線で区切り、いつ始まったかを表示**して読みやすくする。念のため「すべて既読にする」ボタンも付ける |
| 既読の記録先 | ブラウザ（localStorage）。複数のタブで開いていても揃える |
| 吹き出しとの役割分担 | 吹き出しは「いま起きたこと」を一瞬知らせる。未読があるキャラの頭上には ✉ を残す |
| 機械用ログ | 人が読む履歴とは別に、各エージェントの機械用ログを残す。保存場所を設定できる |

## 3. コンテキスト（1回の作業）

### 3.1 定義

**コンテキスト = サブエージェントの1回の呼び出し**（SubagentStart から SubagentStop まで）。
識別子はフックのペイロードの `agent_id`（報告履歴の `taskId`）。

- 許可待ちの記録は、これまで `taskId: null` で書いていた。今回から、状態ファイルの `task.taskId` を入れる。
- すでに書かれている `taskId: null` の記録は、サーバー側で**同じエージェントの、その時刻を含むコンテキスト**（開始 ≦ 時刻 ≦ 終了。終了がまだなら次の開始まで）にまとめる。どれにも当てはまらないものは「時刻の近い記録」として単独の区画にする。

### 3.2 API

`GET /api/reports/contexts?agentId=<id>&limit=<件数>&before=<startedAt>`

```json
{
  "contexts": [
    {
      "taskId": "a4502c07dfad60be4",
      "startedAt": "2026-10-18T05:03:11.500Z",
      "endedAt": "2026-10-18T05:07:40.020Z",
      "state": "done",
      "reports": [ { "seq": 10, "ts": "...", "level": "info", "text": "開始しました", "agentId": "...", "taskId": "..." } ]
    }
  ],
  "nextBefore": "2026-10-17T…"
}
```

- 新しいコンテキストが先。区画の中の報告は古い順（上から読むと流れが分かる）。
- `state`: `running`（終了の記録がない、かつ最新）／`done`（result がある）／`unknown`（終了の記録がないまま次が始まった）。
- `limit` の既定は 5、上限 50。

### 3.3 見せ方（詳細パネルの「報告」欄）

```
┌ 今日 14:03 開始 → 14:07 完了（4分）            未読 1 ┐
│ 14:03  開始しました                                      │
│ 14:05  許可待ち: Bash                                     │
│●14:07  実装が終わりました…                               │
└──────────────────────────────────────────┘
┌ 昨日 22:40 開始 ・ 作業中（…）                          ┐
```

- 区画は**薄い境界線**（1px、背景よりわずかに濃い色）で囲み、区画どうしの間に少し余白をとる。
- 見出しの時刻:
  - 今日なら「今日 14:03」、昨日なら「昨日 22:40」、それより前なら「10/16(木) 09:12」。
  - 年が違えば年も出す。
  - 時刻の上にカーソルを置くと、秒まで含む正確な日時が見える（`title`）。
- 見出しの後半:
  - 「→ 14:07 完了（4分）」
  - 作業中なら「作業中（12分経過）」。経過時間は1秒ごとに更新する。
  - 終わりが不明なら「終了の記録なし」。
- 未読の報告には行頭に ● を付け、区画の見出しに「未読 N」を出す。詳細パネルを開いた時点で既読になるが、**その表示中は ● を残す**（どれが新しかったか分かるように）。次に開いたときには消える。
- 最初は新しい5区画を表示し、「さらに前の作業を表示」で5区画ずつ足す。
- これまでの「進捗ログ」（状態ファイルの直近50件）は置き換える。状態ファイルの `log` は、待機に戻るときに空になるため、履歴の表示には向かない。

レポート画面（全エージェント横断）も、**同じエージェントの同じコンテキストが続く行**を1つの区画にまとめ、同じ見出しを付ける。

## 4. 未読

### 4.1 既読の記録

- localStorage のキー `agentVillage.readMarks`。
- 中身は `{ "<プロジェクトの絶対パス（小文字）>": { "<agentId>": "<最後に既読にした報告の ts>" } }`。
- 記録のないエージェントは、すべての報告が未読の対象になる（§2 の決定）。
- localStorage が使えない環境（プライベートウィンドウなど）では、ページを開いている間だけ覚える。
- 別のタブでの変更は `storage` イベントで受け取り、件数を数え直す。

### 4.2 数え方

`POST /api/reports/unread` に `{ "marks": { "<agentId>": "<ts>" } }` を送る。サーバーは、各エージェントについて「記録より新しい、result・warn・error の報告」を数えて返す。

```json
{ "counts": { "coder-a": { "total": 2, "error": 1, "warn": 0, "result": 1, "latestTs": "…" } } }
```

- 開いたとき、再接続したとき、別のタブから変更が来たときに問い合わせる。
- それ以外は、SSE の `report-added` で手元の件数を増やす。
- エージェントの詳細パネルを開いている間に来た報告は、その場で既読にする（オフィス画面が表示されている場合だけ）。

### 4.3 画面

| 場所 | 表示 |
|---|---|
| エージェント一覧の見出しの右 | `✉ 未読 5件（3人）`。エラーを含むときは赤、含まないときは橙。未読がなければ「未読なし」と薄く表示 |
| ↑を押したとき | 吹き出し型の一覧が開く。未読の多い順に「名前・件数（エラー N）」。名前を押すと、そのエージェントを選んで詳細を開く（＝既読）。下に「すべて既読にする」 |
| 新しい報告が来たとき | ↑のすぐ下に「〇〇から報告（結果）・未読 N件」を5秒間表示し、バッジを1回だけ揺らす |
| 一覧の各行 | 名前の横に件数の丸バッジ（エラーを含むなら赤） |
| オフィス画面 | 未読があるキャラの頭上に小さな ✉（吹き出し・許可待ちの表示中は隠す） |
| ヘッダーの状況サマリー | 変更しない（許可待ちを最優先で出す既存の動作を守る） |

## 5. 機械用ログ

### 5.1 場所と形式

- 既定の場所: `<プロジェクト>/agents/machine-logs/`。
- 1エージェント1フォルダ、1日1ファイルにする: `<場所>/<agentId>/<YYYY-MM-DD>.ndjson`。日付はその PC の現地時刻で決める。
- 1行に1つの出来事を JSON で書く（NDJSON）。追記だけで、消したり書き換えたりはしない。
- `grep`・`jq`・表計算・スクリプトでそのまま読めるように、項目名と型を固定する。

| 項目 | 型 | 内容 |
|---|---|---|
| `v` | 数 | 形式の版。今回は `1` |
| `ts` | 文字列 | ISO 8601（UTC） |
| `event` | 文字列 | `start`／`stop`／`permission` |
| `agentId` | 文字列 | 画面と同じ ID（`agent_type` を小文字・ハイフンにしたもの） |
| `agentType` | 文字列 | Claude Code が渡した `agent_type` そのまま |
| `taskId` | 文字列 / null | コンテキスト（`agent_id`） |
| `sessionId` | 文字列 / null | 親セッションの `session_id` |
| `project` | 文字列 | プロジェクトの絶対パス |
| `cwd` | 文字列 / null | フックが呼ばれたときの作業フォルダ |
| `permissionMode` | 文字列 / null | ペイロードにあれば |
| `transcriptPath` | 文字列 / null | 会話記録のファイル（stop では `agent_transcript_path` を優先） |
| `tool` | 文字列 / null | permission のときのツール名 |
| `message` | 文字列 / null | stop のときの最後の返答（**全文**。人が読む履歴は先頭300文字） |
| `durationMs` | 数 / null | stop のとき、開始からの時間 |

- **書かないもの**: ツールの入力（`tool_input`）。コマンドの引数などに秘密が入ることがあるため。ペイロード全体のコピーも書かない。
- 会話記録の中身は書かず、場所（`transcriptPath`）だけを書く。詳しく調べたいときはそこを開く。

### 5.2 設定

- 保存先: `<プロジェクト>/agents/config/village.json`。
- 中身: `{ "machineLog": { "enabled": true, "dir": "agents/machine-logs" } }`。
  - `dir` は、プロジェクトからの相対パスでも、絶対パスでもよい。
- フック（`bin/agent-village-hook.js`）は、呼ばれるたびにこのファイルを読む。ファイルがない・壊れている場合は既定値で動く。フックは Claude Code の作業を止めてはいけないため、書き込みに失敗しても黙って終わる。
- 画面: 構成画面の一番上に「Agent Village の設定」の欄を置き、機械用ログのオン／オフと場所を変えられるようにする。
  - Claude Code 自体の設定（その下の欄）は、これまでどおり読み取り専用のまま。
  - 実際に書き込まれる場所（絶対パス）と、既定に戻すボタンも表示する。
- API: `GET /api/village-settings`、`PUT /api/village-settings`（`{ machineLog: { enabled, dir } }`）。
  - `dir` が空、制御文字を含む、`.claude` フォルダの中、既存のファイルを指す、作れない — のどれかなら 400 で理由を返す。
  - 場所を変えても、それまでのログは移動しない（画面にもそう書く）。
- `agents/machine-logs/` は `.gitignore` に入れる。

### 5.3 人が読む履歴との違い

| | 人が読む履歴（08） | 機械用ログ（今回） |
|---|---|---|
| 場所 | `agents/logs/<agentId>.ndjson`（固定） | 設定で変えられる。エージェント別・日別 |
| 中身 | 画面に出す文（`text`、300文字まで） | 調査用の項目（セッション・会話記録の場所・所要時間・全文） |
| 使い道 | ダッシュボードの表示 | `grep`・`jq`・スクリプトでの調査 |

## 7. 検証の方針（fix-verify-loop に準拠）

- 機械用ログ: 既定の場所／相対パス／絶対パス／オフ／設定ファイルが壊れている、の5通り。不正な場所は4種類すべて拒否されること。`tool_input` に仕込んだ秘密がどこにも書かれないこと。
- コンテキスト: 正常（開始→許可待ち→終了）／作業中／終了の記録なしで次が始まる／古い `taskId: null` の記録、の4通り。
- 未読: 数える種類（info は数えない）／既読にする操作2種類／再読み込み後も残る／別のタブに反映される／詳細を開いたままの新着は既読になる／すべて既読／✉ の表示と消え方。
- 既存のテスト（test_24・test_projects・test_config）も合わせて、それぞれ複数回実行する。

## 8. 実装メモと検証結果（2026-10-18）

### 8.1 設計から足したこと

- 詳細パネルの並びを「説明 → 報告 → 変更（名前・見た目・アニメーション）」にし、変更欄は最初は閉じた状態にした（§1 の段階 C）。
- 長い報告（最後の返答は300文字まである）は3行で畳み、クリックで全文を開く。開いた状態は、画面が描き直されても保つ。
- サイドバーの「エージェント」タブにも未読の合計を出す（「部屋」タブを開いているときにも気づけるように）。
- サーバー側の作業中の判定は「終了の記録がない、最新の作業」だが、エージェントの状態が作業中でなければ、画面では「終了の記録なし」と表示する（途中で止まった作業が、いつまでも「作業中」に見えないように）。

### 8.2 検証

`docs/context_logs/2026-10-16_tests/test_unread.js`（71項目）を**3回続けて実行し、毎回すべて合格**した。
フックは本物（`bin/agent-village-hook.js`）を、テスト用プロジェクトに対して実行している。

| 観点 | 確認したこと |
|---|---|
| 機械用ログ | 既定の場所・相対パス・絶対パス・オフ・設定ファイルが壊れている、の5通りで、書く場所が設定どおりになる。項目は14個で固定。許可待ちの行に作業の ID が入る。終了の行に返答の全文と所要時間が入る。`tool_input` に仕込んだ秘密はどのファイルにも書かれない |
| 設定の検証 | 空・制御文字・`.claude` の中・ファイルを指す・作れない、の5種類を、理由つきで拒否する。拒否したときは何も保存しない |
| コンテキスト | 作業中／完了／終了の記録なし／古い `taskId: null` の行（含まれる作業に入る・どれにも入らない）、の各形。新しい順、区画の中は古い順。ページ送り |
| 未読 | info は数えない。バッジ・タブ・一覧の各行・頭上の ✉。一覧から開くと既読になる。開いている間に来た報告はその場で既読になり、● は残る。別のエージェントの報告ではお知らせが出て5秒で消える。吹き出しが出ている間は ✉ を隠す |
| 既読の保存 | 再読み込みしても残る。別のタブにも反映される。レポート画面で絞り込むと既読になる。「すべて既読にする」 |
| 構成画面 | 設定欄の表示・不正な場所のエラー表示・保存・既定に戻す。範囲の切り替えで入力中の欄が消えない |

既存のテストもすべて合格した: `test_config.js`（71項目×2回）、`test_projects.js`（58項目×2回）、`test_24.js`（52項目×2回）。

### 8.3 残課題

- レポート画面（全エージェント横断）では、古い `taskId: null` の行が作業の途中にあると、その作業が3つの区画に分かれて見える（隣り合う行だけでまとめているため）。今後のデータには作業の ID が入るので、起きるのは過去の記録だけ。
- 同じ種類のエージェントを同時に2つ動かすと、状態ファイルが1つなので、許可待ちの行の作業 ID と所要時間が、もう一方のものになることがある（02・05 の既存の制約と同じ）。
- 機械用ログは消さずに増え続ける。1日1ファイルなので、古い日付のファイルを手で消せる。自動で消す機能はまだない。
