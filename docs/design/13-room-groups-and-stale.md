# 13. 一覧の部屋ごとのまとめ・古くなった「作業中」の表示（フェーズ② 2-6b）

- ステータス: **実装済み・検証済み（2026-10-19）**。結果は §5
- 位置づけ: `09-ai-office-redesign.md` §10 の 2-6b。`12-unread-reports-and-machine-log.md` §1 の優先度（A: 対応が必要／B: 一目で分かればよい／C: 必要なときだけ）と親子関係（プロジェクト → **部屋 → エージェント** → 作業 → 報告）の、まだ作っていなかった「部屋」の段。

## 1. 一覧を部屋ごとにまとめる

### 1.1 並びと見出し

- エージェント一覧を、**担当の部屋**（`roomId`。待機中で休憩所にいても、担当の部屋に入れる）ごとにまとめる。
- 部屋の並びは `rooms.json` の順。そのあとにフリーデスク（担当の部屋がないエージェント）、休憩所（`room: break` を指定したエージェント）を置く。
- エージェントがいない部屋は出さない。部屋の中は名前順にする。
- 見出しに出すもの（左から）:

```
▾ コーディング部屋  3人        作業中 2  🔒1  ⚠1  応答なし？1  [未読 5]
```

| 表示 | 条件 | 段階 |
|---|---|---|
| 🔒 N | 許可待ちの人数（点滅は一覧の行と同じ） | A |
| ⚠ N | エラーの人数 | A |
| 未読 N | その部屋の未読の合計（12 §4。エラーを含めば赤） | A |
| 作業中 N | 作業中・割当済みの人数（応答なし？は除く） | B |
| 応答なし？ N | §2 | B |

- 段階 A のものがある部屋は、見出しの左に色の帯を付ける。**閉じていても、中に対応が必要なものがあると分かる**ようにするため。

### 1.2 開閉

- 見出しを押すと開閉する。状態はブラウザ（localStorage の `agentVillage.roomGroups`）に、プロジェクトごと・部屋ごとに保存する。
- 保存した状態がない部屋の初期状態:
  - **ダミーキャラ（`tools: []`）だけの部屋は閉じる。**
  - それ以外は開く。
- 閉じた部屋の中のエージェントが選ばれたとき（地図のキャラ・未読の一覧・状況サマリーから）は、その部屋を開く。選んだものが見えなくならないようにするため。
- 閉じていても、許可待ちなどで自動的に開くことはしない（見出しの印で知らせる）。利用者が閉じたものを勝手に開かないため。

## 2. 古くなった「作業中」（応答なし？）

### 2.1 判定

`02-agent-state-model.md` §4.4 は「120秒更新がなければ stale」としていた。ただ、これはフック方式（05）より前の設計だった。今のフックは、開始・終了・許可待ちのときにしか状態ファイルを書かない。
そのため、長い作業はずっと更新がないのが普通で、120秒にすると動いている作業まですべて「応答なし」になる。そこで次のように変える。

- 条件（すべて満たすとき「応答なし？」）:
  - 状態が作業中または割当済み
  - ダミーキャラではない
  - 許可待ちではない（人の返事を待っているだけなので）
  - `updatedAt` から**設定の分数**以上たっている
- 既定は **60分**。構成画面の「Agent Village の設定」で 1〜1440分に変えられる（`agents/config/village.json` の `display.staleAfterMinutes`）。
- データ（状態ファイル）は書き換えない。表示だけを変える（02 §4.4 と同じ）。
- 判定は画面側で行い、10秒ごとに見直す。

### 2.2 見せ方

| 場所 | 表示 |
|---|---|
| 一覧の行 | 状態の欄を「応答なし？（2時間）」にし、点を中抜きの灰色にする。カーソルを置くと「最終更新から 2時間、終了の記録が届いていません。Claude Code 側で作業が止まった可能性があります」 |
| 詳細パネル | 状態の行の下に同じ説明を出す。作業の区画（12 §3.3）の見出しは「終了の記録なし」 |
| 状況サマリー | 「作業中」の数から外し、「応答なし？ N」を薄い色で別に出す |
| オフィス画面 | キャラを少し薄くし、頭上に「Zzz」を出す。名札は常時表示しない（待機中と同じ扱い） |

## 4. 検証の方針

- 部屋: 複数の部屋・フリーデスク・ダミーだけの部屋・エージェントのいない部屋（出ない）。
- 開閉: 初期状態、押して開閉、再読み込み後も残る、閉じた部屋のエージェントを地図／未読の一覧／サマリーから選ぶと開く。
- 見出しの印: 許可待ち・エラー・未読・作業中・応答なし？ の数と、帯の有無。
- 応答なし？:
  - しきい値の前後（境目をまたぐと10秒以内に切り替わる）。
  - 許可待ち・ダミーは対象外。
  - しきい値の変更がすぐ反映される。
  - 不正な値（0・1441・小数・文字）は拒否する。
- 既存のテスト（test_24・test_projects・test_config・test_unread）も複数回実行する。

## 5. 検証結果（2026-10-19）

`docs/context_logs/2026-10-16_tests/test_groups.js`（41項目）を**3回続けて実行し、毎回すべて合格**した。

| 観点 | 確認したこと |
|---|---|
| 部屋のまとめ | `rooms.json` の順。エージェントのいない部屋は出ない。フリーデスクは最後。部屋の中は名前順 |
| 初期の開閉 | ダミーだけの部屋（デザイン部屋）は閉じ、ほかは開く |
| 見出しの印 | 作業中・🔒・⚠・応答なし？・未読の数。帯は許可待ちで橙、エラーで赤。ダミーは作業中にも応答なし？にも数えない |
| 開閉の操作 | 見出しで開閉。再読み込み後も残る。地図のキャラ・状況サマリー・未読の一覧から選ぶと、閉じた部屋が開く |
| 応答なし？ | 3時間前のまま作業中 → 一覧・詳細・サマリー・Zzz と薄い表示。許可待ち・ダミー・完了は対象外 |
| しきい値 | 1分にすると、45秒前の状態が境目をまたいだあと18秒で切り替わった（10秒ごとの見直しの範囲）。別のタブにも SSE で届く。新しい状態が書かれると、すぐ元に戻る |
| 設定の検証 | 0・1441・1.5・"10"・null を拒否し、何も保存しない。画面からの保存・既定に戻す。機械用ログの設定はそのまま残る |

既存のテストもすべて合格した: `test_unread.js`（71項目×2回）、`test_config.js`（71項目×2回）、`test_projects.js`（58項目×2回）、`test_24.js`（52項目×3回）。
`test_24.js` は、最初の1回だけサーバーの起動完了前に始めてしまい、1項目も動かずに止まった（テストの手順の問題）。起動を待ってから3回実行し、すべて合格した。

### 残課題

- フックは作業の途中で状態を書かないため、本当に長い作業も、しきい値を過ぎれば「応答なし？」になる。名前に「？」を付け、説明文でもそう伝えている。途中経過を書くしくみ（定期的な更新）は今回は作っていない。
- 部屋ごとの開閉の状態は、部屋の ID で覚える。部屋の ID が変わる（部屋を消して作り直す）と、初期状態に戻る。
