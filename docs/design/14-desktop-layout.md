# 14. デスクトップ用（横長）の部屋配置と全画面表示（フェーズ② 2-6c の前段）

- ステータス: **実装済み・検証済み（2026-10-19）**。結果は §8。吹き出しが部屋の外に出る件は §8.2 のとおり未解決（ユーザーの判断待ち）
- 位置づけ: `09-ai-office-redesign.md` §10 の 2-6c（吹き出しのはみ出し対策）の前に入れる。
  ユーザーの判断（2026-10-19）: 吹き出しが重なる・隣の部屋にかかる根本の原因は「キャラに対して部屋が小さい」こと。
  まず部屋の大きさを変えて解消し、吹き出しの配置の工夫はそのあとに必要なら行う。

## 1. ユーザーの決定（2026-10-19）

| 項目 | 決定 |
|---|---|
| 配置の種類 | 今のほぼ正方形の配置（744×696）は**モバイル用**として残す。**デスクトップ用**に横長（16:9）の配置を追加する |
| デスクトップ用の大きさ | **今の高さ（696px）はそのまま**、横幅だけを 16:9 に合わせて伸ばす |
| 全画面 | 1920×1080 のモニターに全画面で表示するボタンを追加する |
| 部屋の画像 | 縦横の比率が違うので、デスクトップ用とモバイル用で別の画像を使う |
| キャラ | 両方で同じ画像・同じ大きさ |

検討の経緯: 1920×1080 の半分（960×540）も検討したが、1部屋が 312×172 になり、面積は今（240×224）とほぼ同じで高さが減る。
そのため、重なりの解消にはならないと判断した。

## 2. 寸法

| | モバイル用（square、今のまま） | デスクトップ用（wide、新規） |
|---|---|---|
| 1部屋 | 240×224 | **404×224** |
| 全体（3×3、すき間12px） | 744×696 | **1236×696**（16:9 = 1237.3。整数にするため 1236） |
| キャラ | 64px | 64px（`min(幅, 高さ) / 3 × 0.9` を16の倍数に切り下げ。高さが同じなので同じ値） |

- 部屋が10部屋以上で4段になると、高さが伸びて 16:9 ではなくなる（モバイル用と同じ扱い）。
- 床と壁は16px の小さな絵を繰り返して敷くので、**部屋の幅が変わってもそのまま使える**（別の画像はいらない）。
  家具（机・椅子・壁飾り・脇置き・敷物）も大きさが決まった部品なので共通。
- 別の画像が必要なのは、**部屋全体を1枚で置き換える画像**（09 §6.4 の旧方式）だけ。§4 で扱う。

## 3. デスクトップ用の部屋の型

部屋の中の座標（左上が 0,0。家具・キャラは足元の位置）。高さ方向はモバイル用と同じ。

| 部品 | モバイル用 | デスクトップ用 |
|---|---|---|
| 机 | 4台（x 72/168 × y 124/208） | **6台**（x 76/202/328 × y 124/208） |
| 机の間の立ち位置（机が埋まったあと） | x 120 × y 106/190、隅 x 24/216 | x 139/265 × y 106/190、隅 x 36/368 |
| 壁飾り | x 24/120/216 | x 60/202/344 |
| 脇置き | x 16/224 | x 16/388 |
| 敷物 | 中央（120,150） | 中央（202,150） |
| 休憩所のテーブル | 中央 | 中央（202,150） |
| 休憩所の立ち位置 | 8か所 | 12か所（左右に広げる） |

- 机を6台にするのは、広くなった分キャラどうしの間隔を空け、吹き出しが横に並べるようにするため。
- 部屋パネルの「机（4台共通）」「椅子（4台共通）」は「全台共通」にする。

## 4. 部屋全体の画像（旧方式）

- 配置ごとに別の画像を保存する: モバイル用は今のまま `custom/rooms/<roomId>.png`、デスクトップ用は `custom/rooms/wide/<roomId>.png`。
- アップロード: `POST /api/rooms/:roomId/tile?layout=wide`（削除も同じ）。`layout` がなければモバイル用（今までと同じ）。
- デスクトップ用の画像がない部屋は、**モバイル用の画像を引き伸ばさず**、部品で組み立てた部屋を表示する。
- 部屋パネルには「モバイル用」「デスクトップ用」の2つの欄を出す。推奨サイズ（名札の帯を除いた部分）は 240×208 と 404×208。
  旧来の推奨値 140×120 は、2-2 で部屋の大きさを変えたときから実態と合っていなかったため直す。

## 5. API

- `GET /api/rooms?layout=square|wide`（省略時は square）。配置に合わせた座標と、その配置の `tileUrl` を返す。
  あわせて `layout`（どちらを返したか）と `tileUrls: { square, wide }`（部屋パネル用）を付ける。
- 不正な `layout` は 400。
- サーバー側のほかの処理（エージェントの部屋の判定など）は、部屋の ID だけを使うので配置に関係しない。

## 6. 画面

### 6.1 配置の選び方

- ヘッダーに「表示: 自動／デスクトップ／モバイル」の選択欄を置く。選んだ値はブラウザ（localStorage の `agentVillage.layout`）に保存する。
- 「自動」: 画面の幅が 1200px 以上で、横長のときはデスクトップ用、それ以外はモバイル用。
- 切り替えたときはページを読み込み直す（地図を作り直すため）。

### 6.2 全画面

- ヘッダーに「⛶ 全画面」ボタンを置く。押すとオフィスの地図だけを画面いっぱいに表示する（ブラウザの全画面機能）。Esc か同じボタンで戻る。
- 全画面のときは、画面に合わせて**小数の倍率でも拡大する**（1920×1080 でデスクトップ用なら約 1.55 倍）。
  通常の表示は今までどおり（入るなら整数倍、入らなければ縮小）。
- 全画面でも、キャラを押して選ぶことはできる（一覧は全画面を戻すと見える）。

## 7. 検証の方針

- 両方の配置で、既存の重なりの検証（test_24: 上段の部屋で6体が同時に発言、下段で3体）を行う。
  デスクトップ用では、**吹き出しが話している人の部屋の外に出た数**も数える。
- 部屋数: 初期8部屋／10部屋（4段）／5部屋。机・立ち位置・壁飾りが部屋の中に収まること。
- 部屋全体の画像: デスクトップ用だけ・モバイル用だけ・両方。デスクトップ用がないときに引き伸ばさないこと。
- 全画面: 1920×1080 で倍率と地図の大きさ。キャラのクリック。
- 画面幅: 1024 / 1280 / 1920 で、自動の判定とヘッダーの横あふれ。
- 既存のテストもすべて実行する。

### 8.2 未解決: 後ろの列の机の人の吹き出しが、上の部屋にかかる

| 発言 | 部屋の外に出た吹き出し（デスクトップ用） | 同（モバイル用、比較） |
|---|---|---|
| 同じ部屋で6人が同時 | 6個中 2〜4個 | 6個中 4〜6個 |
| 同じ部屋で3人が同時（企画部屋） | 3個中 3個 | — |

- 横幅を広げたので、吹き出しどうしの重なりや横への押し出しは減った。しかし、**後ろの列（壁ぎわ）の机に座った人の吹き出しは、3人だけでも上の部屋にかかる**。
- 原因は高さ。後ろの列の人の頭のてっぺんは、部屋の上端から 42px（うち16px は部屋名の帯）にある。その上に名札（約12px）と吹き出し（3行で約52px）を置く余地がない。
  部屋の高さ（224px）を変えていないので、横幅を広げても解消しない。
- 選択肢（ユーザーの判断待ち）:
  - A: 吹き出しの置き場所を「話している人の部屋の中」に限る。上に入らなければ、横や下（机の上）に置く。デスクトップ用は横幅が広いので、吹き出しを横長（2行）にして高さを抑える。
  - B: デスクトップ用だけ部屋を高くする（16:9 を保つと全体も大きくなる）。
  - C: 部屋の外にかかるのは許す（重なりはしない）。
