# 11. プロジェクト切り替え（ヘッダーの接続先表示と切り替えメニュー）

- ステータス: **実装済み・検証済み（2026-10-17、未コミット）**
- 位置づけ: フェーズ②の2-4の後に、ユーザーの要望で追加した（`09-ai-office-redesign.md` §10 の表に「2-4b」として記載）。
- 関連: `04-multi-project-integration.md`（インストールルートとターゲットルートの分離。本書はそれを「起動中に切り替えられる」ように拡張する）

## 1. 背景と要望

ユーザーの要望（2026-10-17）:

> デフォルトの画面でどのプロジェクトのエージェントが動いているのかわからないので、接続中のUIの近くに接続プロジェクトのパスを表示させ、かつプロジェクトパスを登録しておけばクリックしてプルダウンで切り替えるようにしたい。

これまでの状況:

- 監視先（ターゲットルート）は、起動時に `--target` → `TARGET_PROJECT_ROOT` → `agents_app` 自身 の順で1回だけ決めていた。画面上にはどこにも表示されず、起動ログの `target project:` 行でしか確認できなかった。
- 別のプロジェクトを見るには、サーバーを止めて引数を変えて起動し直す必要があった。

## 2. 方針

| 論点 | 決定 | 理由 |
|---|---|---|
| 切り替え方式 | **1つのサーバーが監視先を差し替える**（起動し直さない） | ポートが変わらないので、ブックマークや通知の許可がそのまま使える。複数プロジェクトの**同時**表示は、従来どおりポートを変えた別プロセスで行う |
| 切り替え後の画面 | 開いているすべてのタブを**再読み込み**する | エージェント・部屋・内装・レポート履歴のすべてが前のプロジェクトのものになるため。部屋の追加・削除時（`rooms-changed`）と同じ考え方 |
| 登録リストの置き場所 | `agents_app/.agent-village/projects.json`（git管理外） | 特定のプロジェクトではなく、このインストールに属する情報のため。中身はこのPC固有の絶対パス |
| 起動時の監視先 | **従来どおり**（前回の選択は覚えない） | 起動方法ごとの既定の動作（`agent-village` はカレントディレクトリ、`npm start` は自分自身）を変えないため。必要になれば後で追加する |
| 切り替えられる先 | **登録済みのフォルダだけ** | 切り替えAPIに任意のパスを渡せないようにする（§5） |

## 3. 登録リスト

`server/src/lib/projectRegistry.js`。形式:

```json
{ "projects": [ { "path": "D:\\app\\my_project", "label": "my_project", "addedAt": "2026-10-17T..." } ] }
```

- パスは `path.resolve` で正規化して保存する。Windows では大文字・小文字の違いを同じフォルダとして扱う（重複登録を防ぐ）。
- 登録時の検査: 空でない、絶対パス、フォルダが存在する、**`.claude` フォルダがある**。最後の条件は、親フォルダなどを打ち間違えたときに、切り替えでそこへ `agents/` などのフォルダが作られるのを防ぐため。
- 表示名は省略するとフォルダ名になる（最大40文字）。
- 一覧には各項目について次の情報を付ける。
  - `exists`: フォルダがあるか
  - `agentCount`: `.claude/agents/*.md` の数
  - `hookConfigured`: `.claude/settings.json` または `settings.local.json` に `agent-village-hook` が含まれるか
- 登録の解除はリストから外すだけで、フォルダの中身には何もしない。

## 4. サーバー側の切り替え（`server/src/index.js`）

- ターゲットから導かれるパス（`AGENTS_DEF_DIR` など8個）を `setTargetPaths(root)` でまとめて差し替える。
- `loadTarget(root)` で、フォルダ作成 → `rooms.json` の初期コピー → `roomsStore.init` → レポート履歴の読み込み → 定義と状態の読み込み → `/assets/custom` の配信元の差し替え、の順に行う。
- `switchTarget(root)` の流れ:
  1. ファイル監視をすべて閉じる。`watchGeneration` を1つ進め、保留中のタイマーを捨てる。閉じる途中で届いた古い監視のイベントは、世代番号が合わないので無視される。
  2. `loadTarget(新)`。失敗したとき（例: `rooms.json` がJSONとして読めない）は `loadTarget(元)` に戻してエラーを返す。
  3. 監視を開始し、**すべての監視の準備完了（`ready`）を待ってから**、定義と状態をもう一度読み直す（§8 の不具合1）。
  4. SSE で `project-changed` を送る。各タブはこれを受けて再読み込みする。
- 同時に2つの切り替えが来たときは、後から来たほうに 409 を返す。

### API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/projects` | `{ current, projects }`。`current` は現在の監視先で、`registered`（登録済みか）を含む |
| POST | `/api/projects` | `{ path, label? }` を登録する。不正なら 400 と日本語のエラー |
| DELETE | `/api/projects` | `{ path }` の登録を外す |
| POST | `/api/projects/switch` | `{ path }` に切り替える。登録済みの場所だけ。今と同じ場所なら何もしない（`unchanged: true`） |

## 5. 待ち受けアドレスを 127.0.0.1 に限定

切り替えAPIによって、このサーバーは登録済みのフォルダを読み書きできる。同じネットワークの他の端末から操作されないように、待ち受けを `127.0.0.1` に限定した。もともと2-5で予定していた変更を前倒しした。

- 環境変数 `HOST=0.0.0.0` を指定すると、従来どおりネットワークに公開できる（`docs/setup.md` に注意書きあり）。
- ブラウザ通知（2-4）はもともと `localhost` でしか使えないので、普段の使い方は変わらない。

## 6. 画面（`public/js/projects.js`）

- ヘッダーの「接続中」バッジのすぐ左に📁ボタンを置く。表示は2段で、上段がプロジェクト名、下段がパス。
  - パスが長いときは**先頭側を省略**して、末尾（違いが出る部分）を残す。全文はマウスを乗せると表示される。
  - フックが未設定のプロジェクトでは、枠を琥珀色にする。
- ブラウザのタブ名を「プロジェクト名 — Agent Village」にする。権限待ちがあるときは、その前に `(n) 🔒` が付く（2-4）。
- ボタンをクリックすると、切り替えメニューを開く。
  - 登録済みのプロジェクトの一覧。バッジは「接続中」「エージェント n」「フック未設定」「フォルダなし」。項目をクリックすると切り替える。✕で登録を外す。
  - 今の接続先が未登録なら、上に「この接続先を登録する」を出す。
  - 下に登録フォーム（絶対パスと表示名）。エラーはメニューの中に表示する。
  - メニューの外をクリックするか Esc キーで閉じる。
- ブラウザはセキュリティの制限で、フォルダ選択画面からフルパスを取得できない。そのため、パスは文字で入力する。
- 登録フォームの上に「`.claude` フォルダが入っているフォルダを登録する」という一文を常に表示する。その下の折りたたみ「どのフォルダを登録すればいい？」には、次の内容を入れる（2026-10-17 ユーザー要望で追加）。
  - フォルダ構成の例（登録するフォルダに「← ここを登録」の印）
  - よくある間違い（`.claude` そのもの、`.claudegents`、`D:pp` のような親フォルダ）
  - パスのコピー方法、切り替え時に作られるフォルダ、フックの設定が必要なこと（`docs/setup.md` §10）
  - 折りたたみは、登録が0件のときだけ最初から開いておく。そのあとは、ユーザーが最後に開いたか閉じたかを保つ。
- よくある間違いには、サーバー側でも直し方つきのエラーを返す。
  - `.claude` の中を指定したとき: 「その外側のプロジェクトのフォルダ（…）を登録してください」
  - 親フォルダを指定したとき: 中にある `.claude` 付きのフォルダ名を最大3件挙げる

## 7. 検証（2026-10-17）

`test_projects.js` を、隔離したサーバー（ポート4177）と仮の登録リスト（`AGENT_VILLAGE_REGISTRY_FILE`）で実行した。結果は **49項目すべて合格**で、2回続けて実行しても同じだった。実際の4173番と、実際の登録リストには触れていない。

| 観点 | 結果 |
|---|---|
| 登録の検査（空、相対パス、存在しない、`.claude` なし、大文字小文字違いの重複） | すべて400と日本語のエラー。拒否したときはフォルダに何も作らない |
| 切り替え | `project-changed` を配信。一覧・`/assets/custom`・レポート履歴が新しいプロジェクトのものになる。`rooms.json` が初期コピーされる |
| 監視 | 切り替えた後は、前のプロジェクトの状態の変化を無視し、新しいプロジェクトの変化を届ける。戻ったときには、離れていた間の変化も反映される |
| 失敗時の巻き戻し | `rooms.json` が壊れたプロジェクトでは500を返し、元のプロジェクトに戻る。戻った後も監視は動いている |
| 同時の切り替え | 二重に処理されない |
| 待ち受け | LANのアドレス（192.168.x.x）からは接続できない。127.0.0.1 からは接続できる |
| 画面 | プロジェクト名・パス・タブ名・バッジ・エラーの表示・Escで閉じる。**2つのタブが両方とも**再読み込みされ、新しいプロジェクトを表示する |
| 画面幅 | 1024×640 と 1280×720 でヘッダーが横にはみ出さない |
| JSエラー | なし |

2-4のテスト（`test_24.js`）も、サーバーの変更後に6回続けて全項目合格した（§8 の不具合2・3を直した後）。

**登録の案内（§6 の追加分）の検証（2026-10-17）**: 同じ `test_projects.js` に項目を足し、**59項目すべて合格を3回続けて**確認した。

| 観点 | 結果 |
|---|---|
| `.claude` そのもの／`.claude\agents` を指定 | 400。外側のプロジェクトのフォルダのパスをエラーに表示 |
| 複数のプロジェクトを含む親フォルダを指定 | 400。中にある `.claude` 付きのフォルダ名を表示 |
| 案内の一文・フォルダ構成の図 | 表示される。図に「← ここを登録」が入る |
| 折りたたみの開閉 | 登録0件のときは最初から開く。登録があれば閉じている。開いたあと再描画されても開いたまま |

## 8. 検証中に見つけて直した不具合

1. **切り替え直後の状態の変化を取りこぼしていた**: ファイル監視は、開始してから準備が整うまでに少し時間がかかる。その間に状態ファイルが書き換わっても気づかなかった。準備完了を待ち、そのあと読み直すようにした。
2. **2-4のテストが、たまたま合格していた**: 重なりのテストは「3秒待てば全員が席に着く」前提だった。遠い席のキャラは3秒では着かないことがあり、その場合は失敗していた。前回の報告では、通った1回の結果だけを見ていた。全員が目的の部屋に着いてゆれ始めるまで待つように直した。
3. **待機中のゆれで、吹き出しの位置判定が揺らいでいた（2-4の実装）**: 配置の計算に、ゆれている途中の位置（最大3px）を使っていた。そのため、隣り合う2体が逆向きにゆれると判定が行き来した。ゆれる前の位置（`bobBaseY`）で計算し、ゆれ幅の分だけ余白を足すようにした。この修正を外すと4回中1回で跳びが出て、入れると6回中0回だった。あわせて、ゆれを止めるときに元の位置に戻すようにした。これをしないと、ゆれを再開するたびに少しずつ上へずれていく。

## 9. 残課題

- 起動時に、前回選んだプロジェクトを覚えておく機能はない（§2）。
- 登録済みのフォルダを後で消したり移動したりした場合は「フォルダなし」と表示され、切り替えられない。登録を外すことはできる。
- フックが未設定のプロジェクトでも切り替えられる。その場合、エージェントは表示されるが、作業状態は表示されない（バッジで知らせるだけ）。
