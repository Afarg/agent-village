# 15. 導入のやり方（フックの自動設定・キャラの導入）と、構成画面の用語説明

- ステータス: **実装済み・検証済み（2026-10-20）**。結果は §6
- 位置づけ: フェーズ② 2-6 の仕上げの一部。ユーザーの指摘（2026-10-20）から追加した。
  1. 構成画面の「フック」「スキル」「MCP」などは、エンジニアでない人には何のことか分からない。
  2. フックを設定しないとエージェントの動きが表示されないのに、設定のしかたが文書（`docs/setup.md` §10、`docs/manual-install-guide.md` §5）にしかない。

## 1. ユーザーの決定（2026-10-20）

| 項目 | 決定 |
|---|---|
| 用語説明 | 構成画面の項目にマウスを乗せると、何のための仕組みかを説明する小窓（ポップアップ）を出す |
| 導入のしかた | **ボタンで自動設定**する。アプリが `.claude/settings.local.json`（または `settings.json`）にフックを書き足す |
| 入口 | 独立したホーム画面は作らない。ヘッダーの「構成」と状態のまとめ（「対応が必要なものはありません」）の間に **「導入のやり方」ボタン**を置き、押すと**モーダル**で手順を説明する |
| 自動で開く | フックが入っていないプロジェクトを開いたときは、モーダルを自動で開く（「今は表示しない」で、そのプロジェクトでは開かなくできる） |
| タブ（同日追加） | モーダルを **「フックの導入」** と **「エージェントキャラの導入」** のタブに分ける。キャラの導入は手順の案内（§3.3） |

## 2. 用語説明のポップアップ

### 2.1 対象

構成画面の各カードの見出し、上部の項目ボタン（エージェント 3 など）、カードの中の専門用語。

| キー | 用語 | 説明（画面の文言の要旨） |
|---|---|---|
| agents | エージェント | 仕事ごとの「専門の担当者」の設定。オフィスのキャラ1人に対応する |
| skills | スキル | 特定の作業の「手順書」。必要なときに Claude が読んで、そのとおりに作業する |
| commands | コマンド | 「/名前」と打つと決まった指示を渡せる、定型文のショートカット |
| mcp | MCP サーバー | Claude が外部のサービスや道具を使うための「接続口」 |
| plugins | プラグイン | エージェント・スキル・コマンド・フックなどをまとめた「追加パック」 |
| marketplace | マーケットプレイス | プラグインの配布元のカタログ |
| hooks | フック | 「〜したとき、自動でこれを実行する」という決まり。Agent Village はこれで動きを知る |
| matcher | マッチャー | フックを動かす対象の絞り込み。空欄ならすべて |
| permissions | 権限 | Claude が使ってよい操作のルール（許可・確認・拒否） |
| defaultMode | 既定のモード | 確認の出し方の初期設定 |
| additionalDirectories | 追加の作業フォルダ | プロジェクトの外で、Claude が読み書きしてよいフォルダ |
| env | 環境変数 | Claude Code が動くときに渡される設定値 |
| memory | メモリ（CLAUDE.md） | Claude が毎回最初に読む「申し送りメモ」 |
| scopeUser / scopeProject | ユーザー全体 / プロジェクト | 設定が効く範囲 |
| settingsFiles | settings.json / settings.local.json | チームで共有する設定 / 自分の PC だけの設定 |
| sources | 読み込んだファイル | この画面を作るために読んだファイル |

文言は `public/js/glossary.js` に1か所にまとめる（導入のモーダルからも使う）。

### 2.2 動き

- 用語には小さな「?」印を付け、説明があることが分かるようにする（上部の項目ボタンはボタン自体が対象なので印は付けない）。
- マウスを乗せる（0.15 秒）、またはキーボードで選ぶ（Tab）と出る。外す・Esc で消える。
- タッチ操作ではマウスを乗せられないので、「?」を押すと出し入れする。
- 小窓は画面の端からはみ出さない位置に出す。1つだけ出る（`#term-pop` を使い回す）。

## 3. 導入のやり方（モーダル）

### 3.1 ヘッダーのボタン

- 文言は「🧭 導入のやり方」。フックの状態を小さな印で示す: 未導入 = 赤い点、一部だけ = 黄色の点、導入済み = 印なし。
- 押すとモーダル（`<dialog>`）を開く。Esc・閉じるボタン・外側のクリックで閉じる。

### 3.2 「フックの導入」タブ（上から順に）

モーダルの上部にタブを2つ置く: 「① フックの導入」「② エージェントキャラの導入」。自動で開いたときと、フックが必須の分そろっていないときは①、そろっているときは②を最初に開く。

1. **これは何をするものか**: エージェントの動きを表示するには、Claude Code に3つの「合図（フック）」を登録する必要がある、という説明。
2. **今の状態**: 3つの合図ごとに「導入済み（どのファイルか）／未導入」。
   | 合図 | 何が分かるか | 必須か |
   |---|---|---|
   | SubagentStart（エージェントが仕事を始めた） | 作業中の表示 | 必須 |
   | SubagentStop（エージェントが仕事を終えた） | 完了・休憩所に戻る | 必須 |
   | PermissionRequest（実行の許可を待っている） | 許可待ちの吹き出し | 推奨 |
   - 導入済みでも、書かれているパスにフックのプログラムが見つからないときは「プログラムが見つかりません（Agent Village を移動した？）」と出す。
3. **自動で導入する**:
   - 書き込み先を選ぶ: 「自分の PC だけ（`settings.local.json`、おすすめ）」／「チームで共有（`settings.json`）」。
   - 「変更内容を確認」→ 追加される内容と、書き込み先・控えのファイル名を表示 →「導入する」で書き込む。
   - 足りない合図だけを足す（すでにあるものは書かない）。
4. **導入したあとにすること**: Claude Code を起動し直す（起動中の画面には反映されないことがある）→ Claude Code でエージェントに仕事を頼むと、オフィスのキャラが机に移動する。
5. **解除する**: Agent Village のフックだけを取り除く（ほかのフックは残す）。こちらも確認してから行う。
6. **手で設定する場合**（折りたたみ）: この PC のパスを埋めた設定の文章と「コピー」ボタン、貼り付ける場所。

### 3.3 「エージェントキャラの導入」タブ

手順の案内だけを行う（アプリは画像を作らない）。キャラの見た目は、このリポジトリの前段の2つのアプリで作る。

| 段階 | すること | 使うもの |
|---|---|---|
| 1. エージェントを用意する | `.claude/agents/<名前>.md` があれば、その数だけキャラが自動で現れる（初めは色付きの仮の人形）。Claude Code の `/agents` でも作れる | Claude Code |
| 2. 元の絵を用意する | 画像生成 AI などで、腕を下ろした正面立ち・1人だけ・無地の背景のキャラの絵を作る。髪と瞳の色をはっきり変えると、まばたきが失敗しにくい。斜め・横・後ろ向きもあれば歩く向きが増える | `docs/prompt/business-characters-generation-prompts.md` |
| 3. ドット絵にする | PixelForge（`img_to_pixcel_app`）で変換し、フォルダごと書き出す。グリッドは 32 以上（64 がおすすめ）、出力は 128px まで | `http://127.0.0.1:8000/` |
| 4a. 静止画だけ使う | 右の一覧でエージェントを選ぶ →「見た目」→ PNG（正方形・16〜128px・300KB 以下）を選んで「差し替える」 | このダッシュボード |
| 4b. まばたき・歩く動きも付ける | PixelAnimator（`ani_convert_app`）に 3 のフォルダを読み込ませ、出力フォルダを書き出す → エージェントを選ぶ →「アニメーション」→ フォルダごと選んで「アップロード」。アニメーションは静止画より優先される | 同上 |

- 2つのアプリは、どちらも初期設定では 8000 番で起動するので、同時に使うときは片方を `--port 8001` で起動する。
- タブの下に「エージェント一覧を開く」ボタンを置き、押すとモーダルを閉じて右の一覧（エージェント タブ）を表示する。

### 3.4 自動で開く条件

- ページを開いたとき、必須の2つ（SubagentStart・SubagentStop）のどちらかがどの設定ファイルにもなければ開く。
- モーダルの下の「このプロジェクトでは、次から自動で開かない」に印を付けたプロジェクトでは、自動では開かない（localStorage `agentVillage.setupDismissed`、プロジェクトのフォルダごと）。ボタンからはいつでも開ける。必須がそろっているときは、この欄は出さない。
- テストでは、サーバーの環境変数 `AGENT_VILLAGE_SETUP_AUTO_OPEN=0` で自動で開かないようにする（既存のテストは未導入のプロジェクトを使うため）。

## 4. サーバー（`server/src/lib/hookSetup.js`、`index.js`）

### 4.1 API

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/setup/hooks` | 状態: フックのコマンド文字列、合図ごとの導入先、書き込み先の候補ファイル（あるか・読めるか）、必須がそろっているか |
| POST | `/api/setup/hooks` | `{ action: "install" \| "uninstall", target: "local" \| "shared", dryRun: true \| false }`。`dryRun` のときは書き込まず、変更前後の内容を返す |

### 4.2 書き込みの決まり

- コマンドは固定: `node "<Agent Village の場所>/bin/agent-village-hook.js"`（区切りは `/`）。画面から任意の文字列は送れない。
- 書き込み先はターゲットのプロジェクトの `.claude/settings.local.json` か `.claude/settings.json` だけ。ユーザー全体（`~/.claude/`）には書かない。
- 既存のファイルは JSON として読み、ほかの設定（権限など・ほかのフック）はそのまま残す。JSON として読めないときは書かずに、直してもらうよう案内する。
- 足すのは足りない合図だけ。同じファイルに Agent Village のフックがあれば足さない。パスが違う（古い場所を指している）ときは、今の場所に書き換える。
- 解除は、コマンドに `agent-village-hook` を含むものだけを取り除く。空になったグループ・合図・`hooks` は消す。
- 書き換える前に、元のファイルを同じフォルダに控えとして残す（`settings.local.json.bak-<年月日-時分秒>`）。ファイルがなかったときは控えを作らない。
- 書いたあと、もう一度読み直して JSON として正しいことを確かめる。
- 安全: サーバーは 127.0.0.1 だけで待ち受けている（2-4b）。さらに、この API は `Content-Type: application/json` 以外と、ほかのサイトからの要求（`Origin` がこのサーバーと違う）を断る。フックは Claude Code が実行するプログラムなので、外のページから書き込ませない。

## 5. 検証の方針

- サーバー: 空のプロジェクト／ほかの設定やフックがあるファイル／壊れた JSON／一部だけ導入済み／古いパス、のそれぞれで、導入・解除・確認（dryRun）の結果と、控え・ほかの設定が残ることを確かめる。ほかのサイトからの要求と JSON 以外の要求が断られること。
- 画面: 未導入のプロジェクトでモーダルが自動で開く。「今は表示しない」で開かなくなる。導入するとヘッダーの印が消え、構成画面のフックに出る。用語の小窓がマウス・キーボード・タッチで出て、画面からはみ出さない。
- 既存のテストがすべて合格すること（既存のテストの多くは未導入のプロジェクトを使うので、自動で開くモーダルが邪魔をしないか確認する）。

ファイル: `server/src/lib/hookSetup.js`（新規）、`server/src/index.js`（API）、`public/js/glossary.js`・`setup.js`（新規）、`config.js`、`main.js`、`index.html`、`style.css`。

`docs/context_logs/2026-10-16_tests/test_setup.js`（ポート 4186、CDP 9342）で 56 項目。続けて実行して毎回全項目合格した。

| 観点 | 確認したこと |
|---|---|
| 状態 | 空のプロジェクト＝未導入。ユーザー全体の設定にあれば導入済みと数える。古い場所を指すフックは「プログラムが見つかりません」で未導入扱い |
| 導入 | 確認（dryRun）では書かない。新しいファイルを作るときは控えなし。2回目は変更なし。ほかの設定・ほかのフック（同じ合図のものも）を残す。控えの中身は元のファイルと同じバイト列。古い場所は今の場所に書き換え、足りない合図だけ足す |
| 解除 | Agent Village のフックだけを外し、元の内容に戻る。空になった `hooks` は消す |
| 守り | 壊れた JSON には書かない（400、ファイルはそのまま）。JSON 以外・ほかのサイトからの要求は 403。`.claude` の外には何も書かない。`user` は書き込み先に選べない |
| 画面 | 未導入なら自動で開く（①のタブ・赤い点）。「次から自動で開かない」で開かなくなる。確認 → 導入でファイルができ、点が消え、構成画面のフックに出る。導入済みなら②のタブから開く。「エージェント一覧を開く」で閉じて一覧へ。解除で赤い点が戻る |
| 用語の小窓 | カードの見出しすべてに「?」。マウス・キーボード・押す（タッチ）で出る。離れる・ほかを押す・Esc で消える。モーダルの中では Esc で小窓だけ閉じる。1024 幅でも画面からはみ出さない |
| ヘッダー | 1024 / 1280 / 1920 幅で、はみ出さず部品どうしも重ならない |

検証中に見つけて直したこと:
- 1024 幅で、プロジェクトの切り替えボタンが縮まずに「接続中」の上にはみ出していた（今回より前からあった。ボタンの追加で目立つようになった）。ボタンを欄の幅に合わせて縮むようにし、1366px 以下では「導入のやり方」を 🧭 だけの表示にした。テストに「ヘッダーの部品どうしが重ならない」を足した。
- キャラのタブの案内を、詳細パネルの実際の表記（「名前・見た目・アニメーションを変更する」の中の「見た目」「アニメーション（まばたき・歩行）」）に合わせた。

既存のテストには `AGENT_VILLAGE_SETUP_AUTO_OPEN: "0"` を足した（`run_all.sh` の 4176 のサーバーも）。
