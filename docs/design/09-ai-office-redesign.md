## 2. 基本方針

1. **部屋を「レイヤー＋スロット」で組み立てる**。床・壁・敷物・家具・壁飾りを別々の部品にし、
   部屋ごとに部品を差し替えられるようにする（P1/P3/P7）。
2. **画像の規格（サイズ・透過・基準点）を固定し、規格を満たす画像は誰が作っても差し込める**
   ようにする。規格外は理由付きで拒否する（既存の部屋タイル・キャラ画像アップロードと同じ流儀）。
3. **初期状態の部品はすべてコードで描く**（Phaser の Graphics → `generateTexture()`）。
   コード描画の部品とアップロード画像は**同じ部品IDの仕組みで扱い**、区別なく選べる。
   → 外部素材なしで完成した見た目になり、ライセンス問題もなく有料版（agent-village-pro）にも流用できる。
4. 画面全体（Phaserの描画＋HTMLのUI）を同じ木目・暖色の配色で統一する（P2/P6）。

## 3. 寸法とピクセル密度

### 3.1 論理座標とアセット密度

- 論理タイル: **16×16**（`01-visual-concept.md` §1.4 を継承）。
- **部品画像は論理サイズと同じピクセル数（×1）で作る**。
  - 当初案は×2だったが、2-2 の実機確認で方針変更した。一般的な画面（コンテナ約1240×870）では
    表示倍率が1倍になるため、×2の画像はニアレストネイバーで半分に間引かれ、ドットが欠ける。
  - キャラ画像（`output_size=128`）は64pxで表示＝2:1。`grid_size=64` で作ったキャラは1ドット=2pxのため、
    劣化なしで縮小できる。

### 3.2 部屋セル

| 項目 | 旧 | 新 |
|---|---|---|
| 部屋セル（論理px） | 140×120（`rooms.json` で可変） | **240×224 固定**（15×14タイル）。`rooms.json` は `layout.columns` のみ参照 |
| 部屋の間隔 | 14 | 12（木の通路色） |
| 名札帯 | なし | 上部 16px |
| 壁 | なし | 16〜64px（48px） |
| 床 | 全面 | 64〜224px |
| キャラ表示サイズ | `min(w,h)/3*0.9` ≒ 32 | 同じ式（≒67）を **16の倍数に切り下げて 64** |
| 表示倍率 | 整数倍（最小1） | 収まるときは整数倍、収まらないときだけ小数（最小0.5）で縮小 |

- 「キャラは休憩所セルの1/9に収まる」ルール（2026-08-17）は維持する。
- 部屋の寸法は部品の規格と一体のため、`layout.js` に固定した。既存プロジェクトの `rooms.json` に残る
  `cellWidth/cellHeight/gap` は無視する（移行作業は不要）。

## 4. 部屋の構成（レイヤーとスロット）

座標は部屋セル内の論理px（左上が原点、240×224）。スロット位置はサーバー側の `server/src/lib/layout.js` が
一元的に計算し、`/api/rooms` で配信する（クライアントとの二重定義を避けるため）。
基準点はすべて**下端中央**（家具やキャラの足元が床に接する点）。

| 描画順 | レイヤー | スロット | 位置 | 備考 |
|---|---|---|---|---|
| 固定 | 床 `floor` | — | y=64〜224 全面 | タイル敷き詰め |
| 固定 | 壁 `wall` | — | y=16〜64 全面 | 横方向に敷き詰め＋床へ落ちる影 |
| 固定 | 名札帯 | — | y=0〜16 | ウォルナット色の帯に部屋名 |
| 固定 | 敷物 `rug` | `rug` | 中心 (120,150) | 家具より下 |
| 固定 | 壁飾り `wallDecor` | `wall1`〜`wall3` | x=24 / 120 / 216、y=60 | |
| y順 | 脇置き `sideDecor` | `side1` `side2` | (16,112) (224,112) 壁際 | |
| y順 | 椅子 `chair` | 各デスクに付属 | デスク上端+2 | キャラより奥 |

## 5. 画像の規格（アップロード部品）

すべて **PNG・1ファイル 512KB以下・ピクセル数＝下表の論理サイズ（×1）**。「最大」の行はその値以下。

| カテゴリ | サイズ | 透過 | 基準点 | コード描画の初期部品 |
|---|---|---|---|---|
| `floor` 床タイル | **16×16** | 不可 | 敷き詰め | タイルカーペット（グレー）、フローリング（オーク／ウォルナット）、床タイル（ベージュ） |
| `wall` 壁タイル | **16×48** | 不可 | 横に敷き詰め（下5pxが幅木） | 白壁、白壁＋腰壁、アクセントウォール（ネイビー） |
| `rug` 敷物 | 最大 160×96 | 可 | 中心 | ラグ（ネイビー）、丸ラグ（ベージュ） |
| `wallDecor` 壁飾り | 最大 48×40 | 可 | 下端中央 | 窓（街並み）、ホワイトボード、時計、掲示板、業績グラフ、壁掛けモニター、額縁の絵、壁付け本棚 |
| `desk` 机 | **64×32** | 可 | 下端中央（天板の奥端 y=8、前板 y=20〜） | オークのデスク（モニター）、白いデスク（ノートPC）、ローテーブル |
| `chair` 椅子 | **32×32** | 可 | 下端中央 | オフィスチェア（黒／ネイビー） |
| `sideDecor` 脇置き | 最大 32×48 | 可 | 下端中央 | 観葉植物、書類キャビネット、本棚、複合機、ウォーターサーバー、コーヒーカウンター |

- 敷き詰め系（`floor` `wall`）は、上下左右の端がつながるように描く。
- **机の上のモニターなどの背が高い小物は、机の左右の端に置く**。キャラは机の中央に立つため、
  中央に置くと顔が隠れる（初期部品のモニターは左端 x=3〜21）。
- 規格外の画像は、「期待したサイズ」と「実際のサイズ」を両方示して受け付けない（2-3で実装）。
- 2-3 で追加した規則:
  - 「最大」のカテゴリは **8px以上・幅と高さとも偶数px**。基準点（下端中央、敷物は中心）が半ピクセルにずれるのを防ぐため。
  - 「透過不可」は実際に画素を読んで判定する（`server/src/lib/png.js` の `inspectPng()`）。RGBA形式でも全画素が不透明なら受け付ける。
  - インターレースPNGは透過を判定できないため、透過不可のカテゴリでは受け付けない（理由をそのまま表示する）。
- アップロードした部品のファイル名は「元のファイル名（英数字化）＋ランダム6桁」（例: `my-desk-1a2b3c`）。
  - `assets/custom/decor/<category>/` に PNG を手で置いても、ライブラリに表示される（ファイル名は英小文字・数字・ハイフンのみ）。

## 6. 部品ライブラリとデータ

### 6.1 部品ID

- コード描画: `builtin:<category>/<name>`（例: `builtin:desk/oak`、`builtin:floor/walnut-plank`）
- アップロード: `custom:<category>/<id>`
- どちらも同じテクスチャキーの規則でPhaserに登録し、描画側は区別しない。
- 画像ファイルが消えていたら、そのカテゴリの初期部品で代わりに描く（部屋が崩れないように）。

### 6.2 保存場所

- アップロード画像: `assets/custom/decor/<category>/<id>.png`（既存の `assets/custom/` 配下の流儀に合わせる）
- 部屋ごとの選択: `agents/config/rooms.json` の各部屋に `decor` を追加

```json
{
  "id": "coder",
  "label": "コーディング部屋",
  "decor": {
    "floor": "builtin:floor/walnut-plank",
    "wall": "builtin:wall/cream-wainscot",
    "rug": null,
    "slots": {
      "wall1": "builtin:wallDecor/window", "wall2": null, "wall3": "builtin:wallDecor/clock",
      "desk": "builtin:desk/oak", "chair": "builtin:chair/leather",
      "side1": "builtin:sideDecor/plant", "side2": "custom:sideDecor/a1b2c3"
    }
  }
}
```

- `decor` がない部屋（既存データ）は「テーマ既定」の部品で描く＝移行作業は不要。
- 机・椅子は部屋内で1種類にそろえる（4台すべて同じ部品）。

### 6.3 API（追加）

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/decor` | 規格（`spec`）・スロット一覧（`slots`）・アップロード部品（`custom`、カテゴリ別）。builtin の一覧はクライアント側の `parts.js` が持つ |
| POST | `/api/decor/:category` | 部品画像の登録（フィールド名 `image`、§5の規格で検証）→ SSE `decor-library-changed` |
| DELETE | `/api/decor/:category/:name` | 部品画像の削除。使っていた部屋は該当スロットの指定を消してテーマ既定に戻す → SSE `decor-library-changed`・`room-decor-changed` |
| PUT | `/api/rooms/:roomId/decor` | 本文 `{ changes: { <スロット>: <部品ID> \| null } }`。指定したスロットだけ変更 → SSE `room-decor-changed` |
| DELETE | `/api/rooms/:roomId/decor` | 部屋の内装指定を消して初期状態に戻す → SSE `room-decor-changed` |

- **内装の変更ではページを再読み込みしない**。`room-decor-changed` を受けたクライアントは、その部屋だけを描き直す
  （部屋の追加・削除・改名は配置が変わるため、従来どおり `rooms-changed` で再読み込み）。
- `rooms.json` の監視は、ファイルの内容がサーバーのメモリ上の内容と違うときだけ「手で編集された」とみなして
  `rooms-changed` を出す（APIでの書き込みは、そのAPI自身が通知済みのため）。JSONとして読めない編集は無視して、前の設定を保つ。

### 6.4 既存の「部屋タイル（全面画像）」

- 既存の `/api/rooms/:id/tile` は互換のため残し、**「背景画像（全面・旧方式）」**として扱う。
  設定されている部屋では、床・壁・敷物の代わりにその画像を敷き、家具は上に重ねる。

## 7. カスタマイズUI（部屋パネル）

- サイドバーの「部屋」タブ → 部屋を選ぶ → **床／壁／敷物／壁飾り1〜3／机／椅子／脇置き1〜2** の各行に
  - **ドロップダウン**: そのカテゴリの部品を小さな見本画像つきで選択（builtin と custom の両方が並ぶ）
  - **ドロップ領域**: 行に画像ファイルを**ドラッグ＆ドロップ**すると、そのカテゴリの規格で検証 → ライブラリに登録 → そのスロットに即反映
- 変更はその場で画面に反映（SSE経由で他のタブにも反映）。
- 「この部屋を初期状態に戻す」ボタン。
- 2-3 の実装メモ:
  - 各行に「サイズ規格」と現在の部品の見本画像を表示する。ドロップダウンでは、その部屋のテーマ既定の部品に「（既定）」と付ける。
  - 標準部品の見本画像は、Phaser を使わず `parts.js` の描画関数を2Dキャンバスに描いて作る（`builtinPartDataUrl()`）。
  - 休憩所には椅子がないため椅子の行を出さない。机の行は「テーブル」と表示する。
  - パネル下部の「アップロードした部品」から部品を削除できる。
  - 部屋パネルは、エージェントの状態が変わるたびには作り直さない（開いているドロップダウンが閉じてしまうため）。

## 14. 2-4 の実装メモと検証結果（2026-10-17）

### 14.1 実装内容

- **配色**: `style.css` を §8 のトークン（`--wood-*`・`--plaster`・`--accent` など）で書き直した。
  選択中のタブ・項目は真鍮色（`--accent`）。状態の色（待機・作業中・完了・エラー）も暖色系に合わせた。
  吹き出しはクリーム地（`#fbf3e2`）＋焦げ茶の枠・文字。
- **サイドバー**: 幅を 380px に広げた。一覧は単独でスクロールし、項目を選ぶと詳細パネルがタブの55%以上を確保する
  （何も選んでいないときは一覧が全体を使う）。部屋一覧は2列表示で、サムネイルはその部屋の床の部品。
  内装の行は「名前・規格・画像…ボタン」の1行目と、全幅のドロップダウンの2行目に分けた（部品名が切れない）。
- **状況サマリーバー**（ヘッダー中央、`public/js/alerts.js`）: 権限待ち（古い順・経過時間つき）→ エラー → 作業中／割当済み／完了／待機の件数。
  権限待ち・エラーの札をクリックすると、オフィス画面＋エージェントタブに切り替えてそのエージェントを選択する。
  権限待ちがあるときは、ブラウザのタブ名の先頭に `(件数) 🔒` を付ける。
  展示用のダミーキャラ（`tools: []`）は件数にも通知にも含めない（判定 `isDummyAgent` は `store.js` に移した）。
- **ブラウザ通知**: ヘッダーの「通知オン／オフ」で切り替え（設定は `localStorage`）。権限待ちの開始・エラー・完了を、
  **このページを見ていないとき（非表示、またはフォーカスなし）だけ**通知する。権限待ちが解消したら、その通知は閉じる。
  通知をクリックするとページに戻り、そのエージェントを選択する。初回の読み込みや再接続での同期では通知しない。
  通知は `http://localhost` などの安全な接続でのみ使える（ブラウザの制限）。その場合ボタンは無効になり、理由を表示する。
- **名札・吹き出しの重なり対策**（`game.js` の `stackLabels()`）: 名札を先に、吹き出しを新しい順に配置する。
  重なる場合は、ぶつかる箱の上・左右・下の候補から、元の位置に最も近い空き位置へ移す（上を優先、下は最後の手段。キャンバスの外には出さない）。
  移した吹き出しには話し手の頭への引き出し線を描く。新しい吹き出しほど手前に描く。
  配置は0.1秒ごとに計算し（その間は位置がキャラに追従）、一度移した箱は「元の位置がはっきり空くまで」その場所を保つ
  （待機中の上下のゆれで行き来しないため）。
- **吹き出しの改行**（既存の不具合の修正）: 日本語が折り返されず、横に長い1行になっていた。`useAdvancedWrap` を有効にし、
  幅168px（全角約15文字）で折り返す。表示は48文字までで、全文はサイドバーとレポート画面で読める。

**検証中に見つけて直した、自分の実装の不具合**（`docs/error_log.md` 2026-10-17）:

**追記（2026-10-17、2-4bの作業中）**: 上の重なりと跳びの結果は、**たまたま合格した1回分**だった。
繰り返し実行すると、3回中2回は失敗した。原因は2つあった。①テストが3秒で全員が席に着く前提だったが、
